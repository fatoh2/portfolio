# Portfolio review and three concept directions, November 2026

Follows [REVIEW-2026-10.md](REVIEW-2026-10.md), whose list is done. That review asked "is the content
honest and complete". This one asks a different question: **would a client who has seen twenty
developer portfolios remember this one, and message its owner?**

Method: read the code and content, walked the dev build at 1440 and 375, ran the design inspector on
the homepage (measurements below, screenshots in `.taste-skill/before/`), and had a research agent
check current portfolios, libraries and templates on the web. The concept film is
[concept-film.html](../concepts/2026-11/concept-film.html) (open it in a browser, it has a scrubber)
and [concept-film.mp4](../concepts/2026-11/concept-film.mp4).

## 1. Verdict

The site is honest, complete and well built, and it is not yet unmistakable. What is strong is the
**content**: real captures, a playable SOLitaire table, four installable Android builds, a working
copy of the agent's rules layer, a "now building" strip fed by real task files, three languages.
What is generic is the **container**: near-black with acid lime, Space Grotesk, a name as the
headline, numbered sections, a four-step process, a contact form. Move the monogram to another
developer's site and the frame still fits.

No rebuild from scratch. The stack, content model, i18n, captures, tests and deploy flow stay. What
changes is the idea the homepage is built on, the first screen, the type, and the order of proof.

**Copy.** Four headlines fail the swap test (a competitor could use them unchanged): "Ideas, out in

## 4. Three candidate families

Registry check: machines (Stuff Made Here), the mountain ascent (ElsewhereCo) and tatreez
(GoToNature) are taken. None of these three reuses them.

### A. Follow one message

> On this site, **one customer message, "بكم الكنافة؟"**, becomes **the route through everything he
> builds**: it leaves a phone, passes the channel, the rules, the product and the cluster, and comes
> back as the reply.

| Part | Device |
|---|---|
| First screen | "The whole system. One engineer." beside a phone where the message is typed and sent |
| Scroll | the message descends one layer per screen; a rail shows where it is |
| Navigation | the rail itself: Channel, Rules, Product, Cluster |
| Work | each layer holds the real projects that prove it (agent simulator at Rules, products at Product, the CV work at Cluster) |
| Numbers | the rules trace: intent, item, source, price, takeover |
| Live thing | the visitor types their own message and watches it take the same route through the real rules layer |
| Contact | the reply arrives, then "Now send me yours" opens WhatsApp |
| 404 | "Message not delivered" with the route it tried |

- Competitor test: any full-stack engineer can draw a stack. Only this one has the Arabic message, the
  rules gate and the takeover. Passes while the message and the trace are real.
- Sells: the positioning line already on the site. Risk: a long pinned scroll must stay readable on a
  thumb and with script off.

### B. The thread

> On this site, **the chat thread his agents work inside** becomes **the page**: projects are chats,
> status is delivery ticks, and hiring is the human takeover.

| Part | Device |
|---|---|
| First screen | his own agent greets the visitor, with three questions to tap |
| Navigation | a chat list: one row per project, last message and date from the now-building data |
| Status | one tick for in development, two for live |
| Work | "What's live?" returns project cards as messages |
| Contact | "Talk to Fathallah": the agent hands over, and the thread continues on WhatsApp |
| 404 | "This message was deleted" |

- Competitor test: weaker than it looks. The research found that "ask my AI about me" portfolios are
  now a template ([toukoum.fr](https://toukoum.fr) has 70 forks). This version differs because it is a
  demo of the product he sells, in three languages, with a rules layer and a takeover. It has to be
  built so the page reads without typing anything.
- Sells: AI agents on messaging channels, directly. Risk: reads as a chatbot gimmick if the thread is
  the only way in.

### C. The spine

> On this site, **the three scripts he ships in** become **one sheet folded on a spine**: English
> reads in from the left, Arabic and Hebrew from the right, and they meet at the mark.

| Part | Device |
|---|---|
| First screen | the headline in three scripts at once, converging on the FHف mark |
| Navigation | the spine: a bar down the middle holding the mark and the section names |
| Language switch | the page turns on the spine, and the layout arrives mirrored |
| Work | each project is a spread the visitor can turn to see the same screen in the other direction |
| Numbers | set in both numeral systems |
| Footer | the colophon of the sheet, in three scripts |

- Competitor test: the strongest. The research found no award-level trilingual Arabic, Hebrew and
  English personal portfolio; the Awwwards Arabic tag lists four sites, the newest from 2021.
- Sells: craft and the regional market. Risk: says less about AI agents; needs matching captures of
  each product in two directions, which exist for some projects only.

### Recommendation

**A, with C as its language switch.** A carries the argument a buyer needs (what he does, proof at
every layer, one action at the end) and keeps the agent demo as its live thing. The turn on the spine
belongs to the same world as long as it is how a message changes language, and it is the piece no
competitor can copy. B's chat list is a good device for the work index inside A, not a homepage. The
owner chooses; the film shows all three with equal time.

## 5. Whatever the choice

1. First screen says what he does in the largest type. The name moves to the wordmark.
2. One type family with weight (the direction dealt was Schibsted Grotesk 800 at tight tracking), five
   sizes, body at 17 px. Noto Sans Arabic and Hebrew stay.
3. Proof before prose: the playable table, the agent and an install link inside the first three screens.
4. WhatsApp as the primary action; the form second.
5. Drop the process section or fold it into the route; drop the second copy of the pipeline.
6. Add the buyer facts once the owner supplies them: availability, a starting price, a client sentence.

## 6. Libraries and templates

Checked against the npm registry and vendor pages on 2026-11-10 by the research agent.

- **Use the platform first.** CSS scroll-driven animations are in Chrome 115, Safari 26 and Firefox 159;
  same-document view transitions are in Chrome, Safari 18 and Firefox 144. The current portal hero and
  the route in direction A can run on these with an `@supports` fallback. Next 16.2.9 still gates view
  transitions behind `experimental.viewTransition`.
- **Motion 14** (MIT, React 19) if springs, layout or gesture work is needed.
- **GSAP 3.15** is free including the former Club plugins, under Webflow's licence (not open source).
  SplitText per character is untested on joined Arabic; split by word or line.
- **Rive** for one interactive mark, if the monogram should respond to touch.
- **Avoid as visible components:** React Bits, Magic UI, Aceternity. Their effects are recognisable.
  **Avoid:** Theatre.js (last published May 2024), Lenis (reads as a template, capped on Safari).
- **Templates:** none fits. None handles three scripts, and the site already runs on the same stack as
  the best of them ([ncdai/chanhdai.com](https://github.com/ncdai/chanhdai.com), MIT). Take patterns,
  not a starter: Mangham's proof block, shadcn's `rtl: true` registry setting.

Reference portfolios worth opening: [bruno-simon.com](https://bruno-simon.com) (the site is the skill),
[rauno.me](https://rauno.me) (taste in seven lines), [elliott.mangham.dev](https://elliott.mangham.dev)
(the proof dossier), [29lt.com](https://www.29lt.com) and [alefalefalef.co.il](https://alefalefalef.co.il)
(multi-script type).

### 0.2 Spike: choice A4's history behaviour

A client component on today's homepage opens a `<dialog>` and calls `history.pushState` with
`/work/bab` (localised). Production build (`next build`, `next start`), headless Chromium at 390×844,
script `spike/spike_a4.py` on the spike branch. **51 of 51 checks pass on `/`, `/ar` and `/he`:**

| Check | Result |
| --- | --- |
| Opening changes the address to the case page, same document, homepage still rendered | Pass ×3 |
| `usePathname` follows the pushed address | Pass ×3 |
| Back closes the dialog, address back to the homepage, scroll position kept (1500 → 1500) | Pass ×3 |
| Forward reopens the dialog at the case-page address | Pass ×3 |
| Escape closes the dialog and pops the entry; the next Back leaves the site (no dangling entry) | Pass ×3 |
| Refresh while open renders the case page | Pass ×3 |
| After closing, the header links point at the homepage | Pass ×3 |
| The case page's language switch opens the other language's case page (not intercepted) | Pass ×3 |

Two things learned:

- **Analytics counts a sheet as a case-page view.** On open, `@vercel/analytics` queues
  `pageview { path: "/work/bab" }`. Read case-page views together with `sheet_open` after launch.
- **Never render the pathname as text.** The spike printed `usePathname()` in the dialog; on `/` the
  server rendered `/en` (the proxy's rewrite) and the browser `/`, a React hydration error (#418). The build
  must read `history.state` and `location`, not print the pathname.

Not covered: Android's Back gesture on a real phone (device gate).
